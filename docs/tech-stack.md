# 기술 스택 한눈에 보기 (초입자용)

이 저장소에 등장하는 도구들이 각각 "무슨 역할"을 하는지, 처음 보는 사람 기준으로 정리한다.
전체 구조는 [docs/architecture.md](./architecture.md)를, 실습 절차는
[docs/onboarding.md](./onboarding.md)를 참고.

택배 배송 시스템에 비유해서 순서대로 설명한다.

## 1. 땅을 만드는 사람 — OpenTofu

서버(VM)나 네트워크 같은 "물리적인 것"을 만드는 도구다. `tofu apply`라고 명령하면 AWS/GCP/Azure에
서버를 만들거나, 로컬에서는 Lima/libvirt로 가상 컴퓨터(VM)를 만들어준다.

> 비유: 건물을 지을 **땅을 사고 골조를 세우는** 사람. "여기 2코어/4GB짜리 서버 하나 만들어줘"라고
> 코드로 써두면 그대로 만들어진다.

## 2. 그 안에 뭘 채워넣는 사람 — Ansible

OpenTofu가 만든 "빈 서버(VM)"에 SSH로 들어가서 필요한 소프트웨어(k3s, ArgoCD 등)를 설치해주는
도구다.

> 비유: 골조만 세워진 건물에 들어가서 **전기·수도·인테리어를 설치**하는 사람.

이 저장소에서는 딱 두 가지만 설치한다: k3s(3번), ArgoCD(5번).

## 3. 컨테이너를 굴리는 운영체제 — k3s (+ containerd)

Kubernetes를 가볍게 만든 버전이다. 앱(컨테이너 이미지)을 실제로 "실행"하고, 죽으면 재시작하고,
여러 서버에 나눠 배치하는 역할을 한다. `containerd`는 k3s 안에 이미 내장된 "컨테이너를 실제로
실행하는 엔진"이라 Docker를 따로 설치할 필요가 없다.

> 비유: 건물의 **운영시스템 자체**(엘리베이터, 전력 관리). 개별 세입자(앱)가 들어오고 나가는 걸
> 관리한다.

## 4. 앱을 포장하는 표준 — Helm

`docker-compose.yml` 같은 걸 Kubernetes 버전으로 표준화한 것이다. "이 앱을 어떻게 띄워야 하는지"를
하나의 패키지(chart)로 묶어둔다.

> 비유: 이삿짐을 나를 때 각자 다르게 싸지 말고 **표준 규격 상자(chart)**로 포장하는 것. 어떤 앱이든
> 이 상자 규격만 지키면 k3s가 알아서 처리할 수 있다.

## 5. 자동으로 배달해주는 사람 — ArgoCD (GitOps)

git 저장소를 3분마다 스스로 들여다보고, 바뀐 게 있으면 클러스터에 자동으로 반영한다. 중요한 건
**CI가 클러스터로 밀어넣는 게 아니라, ArgoCD가 스스로 git을 당겨온다**는 방향이다.

> 비유: 창고(git)에 새 상품이 들어오면, 매장(클러스터) 직원(ArgoCD)이 스스로 창고를 확인하고
> 진열해두는 것. 창고가 매장에 직접 트럭을 보낼 필요가 없다 → 그래서 로컬/사설망처럼 "외부에서
> 들어올 문이 없는" 곳도 문제없이 동작한다.

## 6. 공사 현장 감독 — GitHub Actions (CI/CD)

`main`에 코드가 push되면 자동으로 1번(OpenTofu)~2번(Ansible)을 실행해준다. 단, **인프라까지만**
담당하고 앱 배포(5번)는 건드리지 않는다.

> 비유: 도면(코드)이 바뀌면 자동으로 공사(서버 생성/설치)를 진행시키는 **현장 감독**.

로컬(사설망) 서버는 이 감독(GitHub이 운영하는 컴퓨터)이 물리적으로 접근할 방법이 없다 — 그래서
self-hosted runner(현장에 상주하는 직원)가 필요하다.

## 7. 도면 검사관 — OPA / Conftest

PR을 올리면, "이 설정대로 지으면 안 된다" 같은 규칙을 자동으로 검사한다.

> 비유: 착공 전에 **건축 도면을 심사**하는 사람. 문제 있으면 착공(merge) 자체를 막는다.

## 8. 로컬 전용 — Lima / libvirt

클라우드 대신 내 컴퓨터에서 "가상 서버"를 만들어주는 도구다. Mac은 Lima, Linux 서버는 libvirt를
쓴다. 둘 다 1번(OpenTofu)이 사용하는 "실행 수단"일 뿐, 역할 자체는 AWS/GCP/Azure와 동일하다.

## 전체 흐름 한 줄 요약

OpenTofu가 서버를 만들고 → Ansible이 k3s/ArgoCD를 설치하고 → k3s가 앱을 실행하고 → Helm으로
포장된 앱을 → ArgoCD가 git을 보고 자동 배포하고 → GitHub Actions가 이 인프라 준비 과정을
자동화하고 → OPA가 실수를 막아준다.
